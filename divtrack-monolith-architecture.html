Monolith Architecture — What Changed
The old microservice architecture (Gateway + 3 services + Redis) was consolidated into one Spring Boot JAR. Every module runs in the same JVM, calls are direct Java methods.
✓1 JVM → vs 5 JVMs — 512MB heap vs 2GB total. Runs on any free tier.
✓In-memory cache (Caffeine) — no Redis server. 10K entries, 90s TTL.
✓Daily price refresh — not every 60s. No WebSocket. Polling at 30s.
✦Dividend Intelligence — Paycheck view, Snowball, Tax Optimizer (unique features).
✓Plan gating — Free (10 holdings, 3 alerts) vs Pro (unlimited, snowball, tax).

Identity & Access
RS256 asymmetric JWT. Auth-service was the only service with the private key. Now it's all in one JAR — same code, same security, zero network hops.
1Register: BCrypt (cost=12), ULID user ID, RS256 JWT signed, refresh token rotated.
2Login: Timing-safe comparison — same error for "not found" and "wrong password".
3Refresh: Token rotation — old token revoked. Replay detection → revoke ALL user tokens.
4JWT payload: {sub, email, name, plan} — plan is in the token. No DB call to check subscriptions.

BCrypt cost=12

Default is cost=10 (~50ms). Cost=12 (~250ms, 5x slower). For attackers: 1 billion passwords × 250ms ≈ 8 years. For users: unnoticeable (login/register is a one-time event).

Refresh token rotation

Each /refresh issues a new token and revokes the old one. If an attacker steals a token and uses it AFTER you've refreshed, the stolen token is already revoked — it won't work. This limits exposure window to near zero.

Portfolio Management
Simple CRUD for holdings and alerts. Plan-gated: Free users get 10 holdings max, 3 alerts max. Pro users get unlimited.
1Add holding: POST /api/portfolio/holdings {ticker, shares} → reads stock from cache → saves → returns projected monthly income.
2Portfolio summary: GET /api/portfolio → total value, monthly income, avg yield, per-holding breakdown.
3Account types: TAXABLE, TRADITIONAL_IRA, ROTH_IRA — used by Tax Optimizer for recommendations.

Plan Gating — the code

@Value("${app.subscription.free-tier.max-holdings:10}") private int maxFreeHoldings; if (!"PRO".equals(plan) && count >= maxFreeHoldings) { throw new PlanLimitExceededException("..."); }
Market Data
Daily price refresh via @Scheduled. Yahoo Finance scraped once per stock. Caffeine cache (90s TTL) — no Redis needed.
1Price refresh — @Scheduled(fixedDelayString = "${app.market.scrape-interval-seconds}"). Defaults to 60s, but at MVP you set it to once-daily after market close.
2Cache — Caffeine: maximumSize=10,000, expireAfterWrite=90s. All stocks cached.
3Direct Java call — Portfolio reads stockRepository.findAll() — same JVM, no serialization.

No WebSocket, no Redis, no real-time

Original architecture had live price push via WebSocket + Redis pub/sub. This was removed. Dividend investors check prices once a day. Polling at 30s is 133x more efficient than WebSocket for this use case. Cloud Run charges per CPU-second — HTTP polling costs ~nothing.

✦ Dividend Intelligence
The unique features that differentiate DivTrack from every other portfolio tracker.

💵 Paycheck View (Free)

Map your monthly bills to specific dividend stocks. See coverage ratio: what % of your expenses your dividends already cover. Shows a progress bar toward FIRE (Financial Independence).

Example: "STRC covers your Netflix. JEPI covers your phone. Keep going — 3 more stocks and your internet is paid forever."

❄️ Snowball Simulator PRO

Year-by-year projection: "If you add $200/mo and reinvest dividends, you reach FI in 8 years instead of 14." Adjustable contribution, reinvest toggle, projection years. Shows portfolio value + monthly income per year.

🧭 Tax Bucket Optimizer PRO

Analyzes every holding's account type (Taxable/IRA/Roth) and recommends optimal placement. High-yield stocks → tax-advantaged accounts. Low-yield → taxable. Saves hundreds per year in taxes.

🍂 Forest Metaphor (Frontend)

Warm tones (amber, forest green), not cold finance blues. Each stock is a tree. Dividends are leaves. Portfolio = a forest. Emotional, not analytical. This is the moat.

DDD Package Structure
Each bounded context is a Java package with strict hexagonal architecture.
io.divtrack/ ├── identity/ // Auth, JWT, users │ ├── domain/ │ │ ├── model/ // User, RefreshToken │ │ ├── service/ // AuthDomainService │ │ └── port/ // UserRepository, RefreshTokenRepository │ ├── application/ // DTOs, IdentityApplicationService │ ├── infrastructure/ // JPA, JwtProvider, SecurityConfig │ └── interfaces/ // AuthController │ ├── portfolio/ // Holdings, alerts ├── market/ // Stocks, scraping, cache ├── dividend/ // ✦ Paycheck, Snowball, Tax (unique) │ └── common/ // BaseEntity, Money, Percentage, exceptions

Extensibility — Add a feature without touching existing code

To add "Portfolio Rebalancing":

1. Create rebalancing/ package parallel to others

2. Define domain model + port interfaces

3. JPA adapter implements repository

4. Application service orchestrates

5. REST controller at /api/rebalancing/

Zero changes to identity/portfolio/market/dividend code. Each context is independently deployable (if you ever split back to microservices).

Why DDD matters here

The Plan enum is in subscription context. The User entity is in identity. The AccountType (taxable/IRA) is in portfolio. These are separate domain concepts — DDD keeps them cleanly separated. When you add Stripe billing, you create billing/. When you add portfolio sharing, you create sharing/. Each stands alone.

Deployment — $0/mo
Three free services. One command to deploy.

1. Cloud Run (Backend)

Google Cloud Run free tier: 2M requests/mo, 360K vCPU-seconds, 1GB egress. Container auto-scales to zero when idle.

gcloud run deploy divtrack \ --source . \ --set-env-vars "SPRING_DATASOURCE_URL=..." \ --set-env-vars "JWT_PRIVATE_KEY=..." \ --memory 512Mi --cpu 1 \ --min-instances 0 --max-instances 2

2. Supabase (Database)

500MB PostgreSQL, free forever. PgBouncer connection pooling included. No 90-day expiry.

3. Vercel (Frontend)

Connect GitHub repo, set NEXT_PUBLIC_API_URL to Cloud Run URL, deploy. Zero config.

OR: Oracle Cloud Always Free

4 ARM cores, 24GB RAM. Run java -jar divtrack.jar directly. SSH in, install Java, copy the JAR, run it. No Docker needed. 95% resources idle at MVP scale.
