🐘 Single DB, 3 Schemas — How It Works

One PostgreSQL container, three logical namespaces. Each service only sees its own schema via currentSchema= in the JDBC URL.
auth.users
id, email, password_hash, name, plan
auth.refresh_tokens
id, user_id, token_hash, is_revoked, expires_at
portfolio.holdings
id, user_id, ticker, shares, avg_cost
portfolio.alerts
id, user_id, ticker, threshold_yield
market.stocks + market.price_history
ticker, price, yield, type, fetched_at

📝 Register Flow

1. Browser → POST /api/auth/register
{ email, password, name }
↓
2. Gateway proxies to auth-service :8081
Spring Cloud Gateway route: /api/auth/** → auth-service
↓
3. AuthController.register()
@Valid validates email format + password ≥8 chars
↓
4. AuthService checks email uniqueness
SELECT EXISTS(... WHERE email=?) → 409 if taken
↓
5. BCrypt.encode(password, cost=12)
~250ms intentionally. Brute-force protection.
↓
6. INSERT into auth.users
ULID generated in @PrePersist → time-sortable ID
↓
7. JwtProvider.generateAccessToken(user)
RS256 sign → { sub: userId, email, name, plan, exp: +15min }
↓
8. Generate refresh token (32 random bytes)
Store SHA-256(rawToken) in auth.refresh_tokens
↓
9. Return 201 { accessToken, refreshToken, user }
Frontend stores accessToken in memory, refreshToken in httpOnly cookie

🔑 Login + Token Refresh Flow

1. Browser → POST /api/auth/login
{ email, password }
↓
2. Find user by email
If not found → BCrypt dummy compare (timing-safe, no email enum)
↓
3. BCrypt.matches(plain, hash)
Timing-safe comparison. Same 401 for wrong email AND wrong password.
↓
4. Return 200 { accessToken, refreshToken, user }
♻️ Token Refresh (every 15 min)
1. Browser → POST /api/auth/refresh
{ refreshToken: "base64url..." }
↓
2. SHA-256(incoming_token) → look up in DB
Not found → 401. Revoked → replay attack detected!
↓
3. If already revoked → REVOKE ALL USER TOKENS
Possible token theft. Force re-login everywhere.
↓
4. Mark old token revoked (rotation)
Issue new accessToken + new refreshToken
↓
5. Return 200 { new accessToken, new refreshToken }

🎟 JWT Token Structure (what's inside)

Access Token (15 min, RS256)

// Header { "alg": "RS256", "typ": "JWT" } // Payload { "sub": "01J9TCRZ3BPQVKMJ0GTS", ← ULID user ID "email": "alice@example.com", "name": "Alice", "plan": "free", ← feature gating "iat": 1700000000, "exp": 1700000900 ← iat + 15 min } // Signature: RSA_SIGN(privateKey, header+payload) // Only auth-service can SIGN. Anyone with public key can VERIFY.

Why RS256 (not HS256)?

🔴 HS256 = ONE secret for sign + verify
→ portfolio-service needs the secret
→ if portfolio-service is hacked, attacker can forge tokens

🟢 RS256 = Private key signs, Public key verifies
→ Only auth-service has private key
→ portfolio/market get public key only
→ Can verify but can't forge — secure

Files that implement this

  • security/JwtProvider.java — sign + verify
  • security/SecurityConfig.java — BCrypt + CORS
  • service/AuthService.java — business logic
  • controller/AuthController.java — HTTP endpoints ← next

📡 Live Price Flow — How a Browser Gets Real-Time Updates

One price update from Yahoo Finance → Redis → ALL connected browsers watching that ticker. Zero polling.

① Market-Data-Service (every 60s)
@Scheduled → scrape Yahoo Finance for STRC, JEPI, etc.
↓
② Save to market.price_history
INSERT stock prices into PostgreSQL
↓
③ Redis PUBLISH prices:live
{"ticker":"STRC","yield":11.5,"price":99.8,"type":"PRICE_UPDATE"}
↓ Redis pushes to ALL subscribers instantly
④ Gateway: RedisSubscriberConfig.receive()
Reactive subscription to prices:live channel
↓
⑤ Parse ticker from JSON
objectMapper.readTree(json).path("ticker").asText()
↓
⑥ PriceFanOutHandler.fanOut("STRC", json)
SessionRegistry.getSessionsFor("STRC") → 3 sessions
↓
⑦ session.send(textMessage(json)) × 3 sessions
Flux.fromIterable(sessions).flatMap(s → s.send(...))
↓
⑧ Browser WebSocket onmessage fires
UI updates dividend yield live — no page refresh needed

🚪 Gateway — Two Jobs in One

Spring Cloud Gateway does double duty: HTTP proxy + WebSocket server.

Job 1 — HTTP Proxy (Spring Cloud Gateway)

GET /api/portfolio/** → :8082
POST /api/auth/** → :8081
GET /api/market/** → :8083

Job 2 — WebSocket Server (our custom code)

ws://gateway/ws?tickers=STRC,JEPI
Browser connects here for live prices
PriceFanOutHandler handles the session
Parses tickers → registers in SessionRegistry
SessionRegistry: "STRC" → {Alice, Bob, Carol}
ConcurrentHashMap — thread-safe
Key trick: order=-1
WebSocketConfig uses order=-1 so our WS handler runs BEFORE Spring Cloud Gateway tries to proxy /ws to a backend service. Without this, SCG would intercept the WebSocket upgrade.

📁 Gateway Files & Their Job

  • WebSocketConfig.java — registers /ws with order=-1
  • PriceFanOutHandler.java — WS session manager + fan-out
  • SessionRegistry.java — ticker→sessions ConcurrentHashMap
  • RedisSubscriberConfig.java — Redis prices:live subscriber

🔑 Before You Can Run: Generate RSA Key Pair

JwtProvider loads RSA keys from env vars at startup. Run these once:

# 1. Generate 2048-bit RSA private key openssl genrsa -out private.pem 2048 # 2. Convert to PKCS#8 format (what Java's KeyFactory expects) openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt \ -in private.pem -out private_pkcs8.pem # 3. Extract public key openssl rsa -pubout -in private.pem -out public.pem # 4. Set in .env (replace newlines with \n for env vars) JWT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvg...\n-----END PRIVATE KEY-----" JWT_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----\nMIIBIj...\n-----END PUBLIC KEY-----"

⚠️ Never commit private_pkcs8.pem to git. Add to .gitignore. Keep it in .env which is already gitignored.
